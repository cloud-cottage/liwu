## 剩余的 4 组手机号重复

从 `audit-full.json` 和 `resolve-duplicates-result` 数据看，`authUid` 去重时手机号与用户存在对应关系。手机号重复很可能是 `authUid` 去重后留下的遗留问题——两个不同用户合并后，两张不同手机号的记录被合并到了同一个 canonical 用户，或者被合并的两个用户原先使用了同一手机号。

去重后仍需要人工确认的 4 组手机号重复数据（需要从 CloudBase 重新查询当前状态）。

## 操作策略

建议使用 CloudBase 控制台或 `tcb` CLI 重新查询当前 `users` 集合，确认以下事项：

1. **手机号重复是否仍然存在**（去重后可能已有一些被自动清理）
2. **登录失败的手机号**是否在重复数据中
3. **`auth_uid` 去重是否完整**（canonical 用户是否保留了正确的 `phone` 和 `auth_uid`）

## 去重原则

- 保留每个手机号中 `last_active` 最新的记录
- `auth_uid` 保留已有登录凭证的那条
- `phone` 必须保持唯一（登录验证码依赖于手机号唯一性）
